## Two-sided cold-start SOP template

```markdown
### 双边平台冷启动 SOP

1. 定义最小交易单元。
2. 选择原子网络。
3. 拆分供给侧和需求侧。
4. 判断关键侧。
5. 手动补齐关键侧。
6. 建立信任与质量门槛。
```

## Interview expression template

```markdown
如果面试官问“你如何拆解这个产品案例/如何做 0-1/冷启动”，可以说：

> 我会先从具体场景和用户任务出发，判断痛点强度和现有方案缺口；然后拆出最核心的不确定性，用最小 MVP 或局部市场去验证。接着我一定会做成败归因：它为什么能成功，是因为结构性时机、未被满足的用户、差异化认知、执行资源，还是形成了数据/内容/供需的正反馈。对于双边平台，我会先定义最小交易单元，拆供需两侧，判断关键侧，再用非规模化方式制造第一批流动性。早期不只看注册量，而看匹配成功率、响应时长、满意度和复用信号。最后把人工运营中发现的卡点沉淀为产品机制和可复制 SOP。
```

## One-line summary patterns

- Demand: **异常场景 → 明确用户 → 强痛点 → 替代方案不足 → MVP 验证 → 平台机会**
- 0-1: **小场景验证 → 小样本反馈 → 假设诊断 → 强爱用户 → 增长杠杆 → 复制闭环**
- Expansion: **原文观点 → 已知事实 → 外部知识 → 底层机制 → 推断边界 → 可验证指标**
- Success: **未覆盖场景 → 低决策成本方案 → 推荐/数据/供给反馈 → 留存增长 → 可防御结果**
- Marketplace: **关键侧 → 原子网络 → 流动性 → 信任质量 → 正反馈 → 产品化复制**
- Named competitors: **表面同类 → 客户JTBD差异 → 价值链控制点 → 供给/质量机制 → 工作流深度 → 壁垒/风险 → PM记忆标签**
- Real platform pain: **模糊需求 → 任务标准化 → 供给分层 → 多阶段质检 → 结果证明 → 反馈回流 → 产品化复制**


## Full independent product case template

```markdown
# 产品名的从 0-1：产品经理案例拆解

> [!summary] 一句话总结
> 它不是【表面品类】，而是通过【核心机制】解决【结构性问题】，并在 0-1 后沿着【发展路径】扩展。

## 公开事实速览
| 维度 | 事实 | 产品经理解读 | 来源 |
|---|---|---|---|

## 这份案例主要补强什么产品能力
| 能力点 | 案例体现 | 面试可迁移表达 |
|---|---|---|

# 1. 机会发现 / 需求洞察
# 2. 它做了什么：产品形态与最小任务
# 3. 竞品格局与破局路径
> 如果有 3–5 个重要相邻竞品，增加“具名竞品差异化矩阵”：定位 / JTBD / 价值链控制点 / 产品形态 / 供给质量机制 / 工作流深度 / 壁垒 / 风险 / PM记忆标签。

# 4. 核心认知差：不是 X，而是 Y
# 5. 真实早期平台痛点：它把什么混乱流程产品化了？
> 对平台 / 基础设施 / B端工作流案例，补充任务定义、流程拆解、供给组织、质量控制、成本效率、结果证明、客户信任、可复制产品化。
# 6. MVP 与最小闭环
# 7. 为什么成功：多因素成功归因
# 8. 冷启动 / GTM
# 9. 0-1 之后的发展路径
# 10. 发展中遇到的问题与解决方式
# 11. 增长杠杆与数据飞轮
# 12. 商业模式与壁垒
# 13. 风险与反面启发
# 14. 和已有案例横向对比
# 15. 迁移到我的 GEO / Agent 项目
# 16. 面试可用总结
# 17. 资料来源与可信度说明
```

## Six-question interview answer template

```markdown
> 我会从 6 个问题拆这个产品：第一，它到底做了什么，不能只说品类；第二，它为什么成功，要拆趋势、痛点、切入口、机制和飞轮；第三，对比竞品或替代方案，它抓到了什么被忽视的机会；第四，0-1 之后它怎么发展；第五，发展中遇到哪些问题；第六，它怎么通过产品化、组织、治理或战略上移解决这些问题。这样拆出来的不是成功故事，而是可复用的产品判断方法。
```
